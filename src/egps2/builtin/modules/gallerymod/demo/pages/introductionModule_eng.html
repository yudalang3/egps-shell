What You See:

This module serves as an introductory feature built into the software, also known as a navigation module or browsing module. Its primary purpose is to provide users with a clear direction to quickly understand and master the core functions of various modules.

The idea for this module originated from valuable feedback from a user who expressed difficulty discovering and utilizing many features in the software. This often required exploring iTools menu items one by one, and the functions behind these menu items were sometimes confusing. The user hoped for a more intuitive way to identify and locate the desired module to improve efficiency and reduce cognitive load.

Based on this, we have worked to classify software modules from multiple dimensions, aiming for comprehensive coverage of potential user needs. Our goal is to create a thorough classification system where users can find solutions and functionalities for any demand. By doing so, we aim to minimize unforeseen scenarios arising from unanticipated needs, ensuring a smooth user experience.

Thank you for your attention and support. We will continue to optimize and improve the modules to provide more user-friendly and efficient services. If you have any questions or suggestions, feel free to reach out to us.

How We Classify

We plan to classify the software modules from four dimensions to help users quickly understand and master the software's usage.

  1. By functional nature: General types of functionality such as professional computational features, visualization tools, etc.
  2. By application field: Classification from the perspective of various disciplines, such as genomics and transcriptomics.
  3. By module complexity: Classification based on development difficulty, time, etc., where higher complexity often means more functionality.
  4. By dependency on the main framework: As an integrated system, modules depend on the main framework to varying degrees.

Classified by Functional Nature

Type Name Notes Examples
Large Complex Visualization Comprehensive functionality with long development time. A single module can meet diverse user needs. Heatmap, Venn diagram, phylogenetic tree visualization, alignment diagram
Simple Visualization Simple development and single functionality, addressing specific user needs. These modules, with enhancement, can evolve into complex visualization modules. Tangle diagrams, dot plots, chord diagrams
Utilities This series of modules covers fundamental functions such as basic string processing and file operations, significantly improving efficiency in daily data handling and file management. Fasta sequence extraction, set operations, string manipulation
Professional Computation Modules tied to specific professional methods, including complex format conversion and support for large text file visualization and editing tools. Blast, BWA, MAFFT tools; evolutionary tree construction via NJ method, Sankoff algorithm, etc.
Console Modules Integrated modules with similar functionality for processing identical input files, offering an interactive platform for data analysis and result visualization. VCF tools, comprehensive FASTA operations
Workflow Modules Collaborative modules forming task-specific workflows, enhancing efficiency and convenience by encapsulating operations. Data loaders, Gene-to-Gene Tree workflows

Simple visualization modules are valuable because developing a large visualization module is time-intensive. Often, a single analysis requires just one chart with a fixed style, making these simpler modules practical.

Classified by Application Field

Type Name Notes Examples

Biological Evolution Focused on evolutionary functionalities. Phylogenetic tree construction and visualization
Population Genetics Focused on population genetics. Positive selection detection, diversity calculation, etc.

Initially, this software was mainly applied in evolution, population genetics, and data visualization, now expanding into other areas.

Classified by Dependency on Main Framework

All modules are part of an integrated system but vary in their dependence on the main framework. This classification is helpful for developers creating plugins and for users to understand module interrelations.

Index Type Name Notes Examples
1 Standalone Modules Modules operate independently, requiring minimal framework interaction. Tangle diagrams
2 Using VOICM Framework Modules use the VOICM universal framework for input and execution. Quick histogram
3 Feedback and Notifications Modules depend on the framework for notifications and feedback. Statistics-related modules
4 Progress Bar and Reusable Components Modules depend on framework features like progress bars and history tracking. Complex computation modules
5 Using Other Modules Modules invoke functionalities from other modules. Gene-to-Gene Tree
6 Full Framework Utilization Modules fully utilize all framework features. Heatmap, Genomic Mutation Presenter

VOICM stands for Versatile Open Input Click Module. It integrates three software operation modes and effectively addresses parameter explosion, improving software development efficiency while supporting reproducible analysis.
